# GitHub 公开成果展示区设计

## 目标

在首页中展示 MoonInAI 当前最受欢迎的三个 GitHub 开源仓库，以可验证的开源成果支撑个人介绍中的“开源 Skill”与“公开建造”主张，并引导访客进入个人 GitHub 主页。

## 范围

第一版只展示手动维护的 GitHub 仓库卡片，不接入 API、不展示 X 帖子、不展示图库。

## 页面位置与信息流

在 `Build Method` 后、现有 `Current Build` 前新增 `Proof of Work` 区域。访客先理解构建方法，再看到实际成果，最后进入正在公开构建的项目和联系入口。

区块由标题、总览数据和三张仓库卡组成：

- 标题：`Proof of Work`，副标题说明这些是可验证的公开成果。
- 总览数据：`03 REPOSITORIES / 1,511+ STARS / OPEN SOURCE`。
- 仓库卡：名称、简要用途、Star、Fork、仓库链接和 `VIEW REPO` 操作。
- 底部链接：跳转到 `https://github.com/chenjin-cmd`。

## 视觉与交互

使用深色档案面板，与浅色主体形成区隔；保留网站既有的橙色强调、编号、等宽字体和工程感。三张卡片桌面端并列，窄屏改为单列；悬停时卡片上移并显露橙色边线。所有仓库链接在新标签页打开，并附 `noopener`。

## 验证

- 为三张仓库卡、准确的链接和关键数据增加静态测试断言。
- 运行 `npm test`。
- 检查窄屏样式与链接安全属性。

## 非目标

- 不实时同步 GitHub 数据。
- 不在第一版加入 X 帖子或图片墙。
- 不修改现有服务、方法或联系区内容。
