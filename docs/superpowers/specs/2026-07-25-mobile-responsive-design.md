# MoonInAI 移动端响应式改造设计

## 目标

让 MoonInAI 在 320px 至 860px 视口中完整可读、可操作且无横向溢出，同时保留桌面端现有的工程蓝图与 AI 系统视觉语言。

## 已确认的体验决策

- 移动端首屏优先展示 AI 神经核心视觉，再展示品牌标题、简介与主要行动按钮。
- 现有横向导航在移动端替换为固定品牌栏和全屏菜单。
- 采用“内容重排”而非单纯缩小桌面布局：双栏切换为单栏；纯装饰性指标按需隐藏；所有核心内容与章节入口保留。

## 结构与组件

### 移动端导航

- 在 `index.html` 新增菜单按钮、全屏导航层和关闭控件。
- 菜单沿用既有 `#about`、`#service`、`#method`、`#build`、`#contact` 锚点，不新增路由或内容来源。
- 菜单打开时禁用页面背景滚动；点击菜单链接、关闭按钮或按 Escape 都会关闭菜单，并把焦点返回菜单按钮。
- 菜单控件带有 `aria-expanded`、`aria-controls` 与清晰的中文辅助文本。

### 内容重排

- Hero 在 860px 以下改为单栏，神经核心排在品牌文案之前；主按钮垂直堆叠并占满可用宽度。
- About、Build、Contact 等双栏或多栏区域在小屏改为单栏；服务与作品列表移除只用于桌面展示的图表、缩略图、分隔列和统计装饰。
- 工程蓝图保留主图和核心说明，压缩或隐藏无法在小屏可靠阅读的极小标注。
- 联系方式与长字符串允许在单词边界不足时安全换行，不会被固定宽度网格撑出视口。

### 防溢出规则

- 使用 `minmax(0, 1fr)`、`min-width: 0` 与弹性文字换行，避免网格和子元素扩大页面宽度。
- 将手机上的固定宽度、`white-space: nowrap` 和过大的间距替换为受视口限制的尺寸；仅在保留单行语义时使用截断。
- 图片、画布和 SVG 均保持容器内缩放；装饰性固定元素在移动端不参与布局。
- 在 iOS 安全区与动态视口下使用 `svh` 和 `env(safe-area-inset-*)`，保证固定导航和首屏不会被浏览器界面遮挡。

## 响应式策略

- `> 860px`：保持当前桌面布局。
- `601px–860px`：平板单栏优先，保留较多辅助信息与较大的神经核心。
- `320px–600px`：手机模式，紧凑间距、全屏菜单、单列内容与不小于 44px 的主要触控目标。

## 交互与降级

- 现有入场、雷达与信号动效在 `prefers-reduced-motion: reduce` 下保持静态且可读。
- 全屏菜单不依赖 JavaScript 才能暴露核心链接：JS 负责开关、焦点与滚动锁定，链接结构仍为普通锚点。
- 触摸设备不依赖 hover 才能读取内容或完成导航。

## 验收与测试

- 在 320、375、390、768 和 860px 宽度检查页面 `scrollWidth` 不超过 `clientWidth`。
- 所有章节可通过菜单到达；菜单可以通过鼠标、触控、键盘 Enter/Space 和 Escape 操作。
- 主要链接与按钮的可点击区域至少为 44px；文字和联系方式不被裁切。
- `npm test` 通过；补充静态测试，覆盖菜单语义和关键移动端 CSS 规则。
- 在桌面宽度复查 Hero、服务列表、Build 和 Contact 的原布局没有被移动端规则影响。
